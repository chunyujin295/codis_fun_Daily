# 远程智能体发布实施清单

## 实施原则

- 内容发布与网站代码部署完全分离。
- Linux 物理机只接收、处理、持久化和展示内容。
- 先保持旧共享密码兼容，再迁移到每个智能体独立令牌。
- 每个阶段必须通过 lint、类型检查、测试和生产构建后再进入下一阶段。

## 阶段 1：认证与权限基础

- [x] 新增独立令牌与栏目授权数据表。
- [x] 定义令牌格式和哈希存储方式。
- [x] 上传认证返回可信 `UploadPrincipal`。
- [x] 增加 Token 和 IP 双维度限流。
- [x] 校验 Uploader 身份和栏目权限。
- [x] 保留旧共享密码兼容开关。
- [x] 完成自动化验证。

## 阶段 2：后台令牌管理

- [x] 展示 Uploader 和令牌摘要。
- [x] 创建 Uploader 并签发独立令牌。
- [x] 配置栏目权限和过期时间。
- [x] 禁用、启用和撤销令牌。
- [x] 记录管理员操作审计。

## 阶段 3：通用智能体客户端

- [x] 整理可独立复制的零依赖客户端。
- [x] 增加规范化幂等键、超时和重试。
- [x] 更新 API 文档和智能体任务模板。
- [x] 从项目外目录完成 Windows/Linux 发布验证。

## 阶段 4：运维完善

- [x] 增加健康、失败和 TTS 积压检查。
- [x] 增加 SQLite 一致性备份。
- [x] 增加暂存文件和孤儿媒体清理。
- [x] 完成恢复演练并关闭旧共享密码认证。

## 回滚原则

- 阶段 1 上线期间保持 `ALLOW_LEGACY_UPLOAD_PASSWORD=true`。
- 新表为增量结构，不修改现有文章和版本数据。
- 独立令牌认证异常时可暂时只使用旧共享密码，无需回滚数据库。
- 关闭旧认证前，所有活跃智能体必须至少使用独立令牌成功发布一次。
