# Linux、Docker 与 FRP 部署

## 1. 环境准备

```bash
cp .env.example .env
```

编辑 `.env`，设置以下必填项：

| 变量                           | 说明                                         |
| ------------------------------ | -------------------------------------------- |
| `ADMIN_PASSWORD`               | 管理员密码，首次启动写入慢散列               |
| `UPLOAD_PASSWORD`              | 迁移期智能体共享上传密码，首次启动写入慢散列 |
| `ALLOW_LEGACY_UPLOAD_PASSWORD` | 全部智能体改用独立令牌后设置为 `false`       |
| `TTS_MASTER_KEY`               | 32 字节随机值的 Base64，加密讯飞凭据         |
| `PUBLIC_BASE_URL`              | 站点公网地址，如 `https://codis.fun/Daily`   |

> 正式使用前必须轮换曾在聊天或截图中出现过的讯飞凭据。

服务启动后，管理员应在 `/Daily/admin` 的"智能体"页为每个远程智能体签发独立令牌，并限定允许发布的栏目。独立令牌明文只显示一次。

### 修改管理员密码

修改 `.env` 中的 `ADMIN_PASSWORD`，重启服务即可自动生效：

```bash
# 1. 修改 .env 文件
ADMIN_PASSWORD=你的新密码

# 2. 重启服务
docker compose restart  # Docker 部署
# 或
npm run build && npm run start  # npm 部署
```

> 服务启动时会自动检测环境变量中的密码并更新数据库，无需手动操作。

## 2. Docker 部署（推荐）

```bash
docker compose up -d --build
docker compose ps
```

应用默认监听 `127.0.0.1:5010`。修改端口：

```bash
DAILY_PORT=8080 docker compose up -d --build
```

数据持久化在 Docker 卷 `daily-knowledge-data` 中，包含 SQLite、图片和音频。

```bash

```


### systemd 服务（生产推荐）

> **Node.js 版本要求**：项目需要 Node.js >= 22.13.0，推荐使用 v24+。

1. 生成服务文件（自动填充当前路径）：

```bash
NODE_PATH=$(dirname $(readlink -f $(which node) 2>/dev/null || echo $(which node)))

cat > ~/.config/systemd/user/daily.service << EOF
[Unit]
Description=Daily Knowledge Timeline
After=network.target

[Service]
Type=exec
WorkingDirectory=$(pwd)
EnvironmentFile=$(pwd)/.env
Environment=PORT=5010
Environment=HOSTNAME=0.0.0.0
Environment=DATA_DIR=$(pwd)/data
Environment=DATABASE_PATH=$(pwd)/data/daily-knowledge.db
Environment=PATH=$NODE_PATH:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
ExecStart=$NODE_PATH/node node_modules/next/dist/bin/next start --port 5010 --hostname 0.0.0.0
Restart=always
RestartSec=3

[Install]
WantedBy=default.target
EOF
```

2. 启用并启动：

```bash
systemctl --user daemon-reload
systemctl --user enable --now daily
systemctl --user status daily
```

查看日志：

```bash
journalctl --user -u daily -f
```

### 重新部署

代码更新后，拉取最新代码并重新部署：

**Docker 部署：**

```bash
cd /path/to/codis_fun_Daily
git pull
docker compose down && docker compose up -d --build
```

**systemd 部署：**

```bash
cd /path/to/codis_fun_Daily
git pull
npm ci
npm run build
systemctl --user restart daily
```

**查看部署状态：**

```bash
# 检查服务是否正常
curl -s http://127.0.0.1:5010/Daily/api/health/ready

# 查看服务状态
systemctl --user status daily

# 查看实时日志
journalctl --user -u daily -f
```

## 4. nginx 反向代理

在现有站点的 nginx 配置中添加：

```nginx
# 尾斜杠重定向到无尾斜杠
location = /Daily/ {
    return 301 /Daily;
}

# 代理到应用
location /Daily {
    proxy_pass http://127.0.0.1:5010/Daily;
    proxy_http_version 1.1;
    client_max_body_size 25m;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
}
```

> ⚠️ **体积上限有两层**：应用自身按「HTML ≤ 10 MB、音频 ≤ 20 MB」校验（超出返回 413 `ARTICLE_TOO_LARGE` / `AUDIO_TOO_LARGE`），
> 但 nginx 默认 `client_max_body_size` 只有 **1 MiB**，会在请求到达应用前直接 413。上面的 `client_max_body_size 25m`
> 就是为 /Daily 放宽这一层 —— 不加的话，智能体推送 >1 MiB 的 HTML 或音频都会被 nginx 拦下，且报错不带业务错误码，
> 排查时容易误以为应用校验太严。
>
> ⭐ **生产实测（2026-09-11）**：文章接口 800 KB 放行、1.1 MB 即被 413 拦下 —— 说明当前生产 nginx **仍是默认 1 MiB**。
> 请务必把上面的配置应用到生产并 `nginx -t && reload`；在调大之前，智能体应按 1 MiB 有效上限（建议 ≤ 950 KB）执行，
> 相关提示词已按此书写。

修改后重载：

```bash
sudo nginx -t && sudo systemctl reload nginx
```

## 5. FRP 内网穿透

### 拓扑

```text
用户 → https://codis.fun
     → 云服务器 nginx (SSL 终止)
     → frps → 加密隧道
     → 本地 frpc → nginx:5006 → 应用:5010
```

### frpc 客户端配置

```toml
[[proxies]]
name = "codis-daily"
type = "http"
localIP = "127.0.0.1"
localPort = 5006
customDomains = ["codis.fun"]
```

frpc 将 `codis.fun` 的所有流量转发到本地 nginx 5006 端口，nginx 再根据路径分发到各个服务。

### 云服务器 nginx 配置

公网服务器需配置 SSL 证书和 FRP 转发，具体参见已有的 `codis-fun` 站点配置。
