## 2. 产品概述

### 2.1 产品目标

建设一个面向每日内容发布的中文网站。多个自动化智能体每天生成新闻或专业知识类 HTML 文章，通过受保护的接口上传；站点依据日期、栏目、标签和上传者等元数据完成自动分类，并以具有动态交互的“时间树”作为主页核心浏览方式。

### 2.2 成功标准

- 智能体无需人工登录网页即可稳定上传文章。
- 未持有有效凭据的请求无法上传或修改内容。
- 上传内容不能在读者浏览器中执行任意脚本或破坏站点页面。
- 文章上传成功后，能够按站点时区、日期和栏目自动出现在正确位置。
- 读者进入主页首屏即可看到时间轴和真实文章，不需要先越过宣传页。
- 项目可直接通过 npm 运行，并提供等价的 Docker 部署方式。

### 2.3 用户角色

| 角色 | 主要任务 | 权限边界 |
|---|---|---|
| 读者 | 浏览时间树、按栏目或日期筛选、阅读文章 | 只读，无需登录（建议默认） |
| 上传智能体 | 携带凭据和元数据上传文章 | 只能创建内容；不能修改栏目配置或其他上传者内容 |
| 站点所有者 | 设置凭据、栏目、站点时区和部署参数，查看审计信息 | 通过服务器配置管理；MVP 暂不要求网页后台 |

## 3. 已确认需求

1. 部署以 npm 为首选，同时支持 Docker。
2. 支持自动化智能体上传其每日生成的 HTML 文章。
3. 上传必须经过由站点所有者设定的密码或等价密钥校验。
4. 文章具有日期、栏目、标签、上传者等结构化信息，上传后自动分类。
5. 初始栏目示例包括“科技新闻”“医疗”“密码学”，实际栏目可配置。
6. 主页采用明显、动态、交互性强的时间线；视觉隐喻倾向于“树干 + 树叶”。
7. 本阶段先交付需求文档和设计文档供审核，并创建 Git 仓库。

## 4. MVP 范围

### 4.1 本期包含

- 公开阅读主页：按日期分段展示文章。
- “时间树”交互：中央树干、日期节点、栏目分枝和文章叶片卡片。
- 栏目筛选和日期定位。
- 文章详情页。
- 单篇文章上传 API。
- 上传凭据校验、请求限流、载荷大小限制和审计记录。
- 元数据校验、服务端时间归类、HTML 安全净化、内容去重和幂等处理。
- 栏目与站点时区配置。
- 空状态、加载状态、错误状态和上传结果反馈。
- npm 开发/生产运行脚本、Dockerfile、Compose 示例、持久化卷和健康检查。
- 基本测试、部署说明、备份与恢复说明。

### 4.2 本期不包含

- 读者注册、评论、点赞、收藏和订阅。
- 智能体在网页中编写文章。
- 富文本编辑器。
- 完整网页管理后台。
- 自动抓取外部网站。
- AI 自动改写、摘要或自动判断栏目。
- 批量上传、审批工作流、邮件/即时消息通知。
- 多机水平扩容和多租户。

以上能力可在后续版本按实际使用情况增加。

## 5. 核心业务流程

### 5.1 智能体上传

1. 智能体生成 HTML 正文和结构化元数据。
2. 智能体使用 HTTPS 请求上传接口，并在 `Authorization` 请求头中携带站点所有者分配的密钥。
3. 服务端依次执行：认证、限流、请求体大小检查、字段校验、栏目校验、时间归一化、HTML 净化、内容摘要计算和幂等校验。
4. 校验通过后，服务端保存文章和审计信息，并返回文章 ID、最终 URL、内容摘要及归类结果。
5. 同一个幂等键重复提交相同内容时返回原结果；同一个键对应不同内容时拒绝并提示冲突。
6. 上传成功的文章自动出现在对应日期和栏目中（是否需要先审核见待决策事项）。

### 5.2 读者浏览

1. 读者打开主页，首屏看到最近日期、时间树主干和至少一组文章叶片。
2. 读者可沿时间树滚动，或使用栏目筛选、日期定位缩小范围。
3. 日期节点下按栏目形成分枝，同栏目的多篇文章按发布时间倒序排列。
4. 点击文章叶片进入详情页；返回时尽量恢复原滚动位置和筛选状态。

## 6. 内容与字段定义

### 6.1 上传请求字段

| 中文名 | 字段 key | 类型 | 必填 | 规则 | 来源 |
|---|---|---:|:---:|---|---|
| 协议版本 | `schemaVersion` | string | 是 | MVP 固定为 `1` | 上传者 |
| 外部文章 ID | `externalId` | string | 是 | 上传者范围内唯一，1–100 字符 | 上传者 |
| 标题 | `title` | string | 是 | 去除首尾空白后 1–120 字符 | 上传者 |
| 摘要 | `summary` | string | 否 | 最多 300 字符；空缺时不在 MVP 自动生成 | 上传者 |
| 栏目 | `category` | string | 是 | 必须匹配已启用栏目的稳定 slug | 上传者 |
| 内容时间 | `publishedAt` | ISO 8601 string | 是 | 必须带时区偏移；服务端转为站点时区归档 | 上传者 |
| 标签 | `tags` | string[] | 否 | 最多 10 个；每个 1–30 字符；规范化去重 | 上传者 |
| 语言 | `language` | string | 否 | 默认 `zh-CN` | 上传者 |
| 来源链接 | `sourceUrl` | string | 否 | 仅允许 `https` URL | 上传者 |
| HTML 正文 | `html` | string | 是 | UTF-8；建议默认上限 2 MiB；必须通过净化 | 上传者 |
| 上传者 | `uploaderId` | string | 否/派生 | 推荐由密钥身份在服务端派生，不信任正文自报 | 服务端 |

### 6.2 服务端生成字段

| 字段 | 用途 |
|---|---|
| `id` | 内部稳定标识 |
| `slug` | 人类可读且唯一的文章 URL 标识 |
| `contentDate` | 根据 `publishedAt` 和 `SITE_TIMEZONE` 计算的归档日期 |
| `contentHash` | 对规范化内容计算的摘要，用于校验与去重 |
| `createdAt` / `updatedAt` | 服务器记录时间 |
| `status` | `published`、`quarantined`、`archived` 等状态 |
| `sanitizerVersion` | 记录使用的 HTML 净化规则版本，便于后续迁移 |

### 6.3 栏目字段

| 字段 | 规则 |
|---|---|
| `slug` | 稳定、唯一，供 API 使用；改显示名时不改变 |
| `name` | 面向读者的栏目名，如“科技新闻” |
| `color` | 时间树分枝和标签的主题色，同时必须有文本标识 |
| `order` | 同一天内的栏目展示顺序 |
| `enabled` | 是否接受新上传和在筛选器中展示 |

## 7. 功能需求与验收条件

| 编号 | 功能 | 需求 | 核心验收条件 |
|---|---|---|---|
| FR-01 | 时间树主页 | 按日期、栏目、文章形成树状时间线 | 最近日期和真实文章在首屏可见；日期顺序稳定；同日多栏目不混排 |
| FR-02 | 筛选与定位 | 支持栏目多选/单选和日期定位 | 筛选后 URL 可表达状态或刷新不丢失；无结果时显示清晰空状态 |
| FR-03 | 文章详情 | 展示标题、日期、栏目、标签、上传者和安全正文 | 刷新可直接访问；危险标签和事件属性无法执行 |
| FR-04 | 上传认证 | 仅合法密钥可调用上传接口 | 缺失/错误密钥返回通用 401；日志中不出现原始密钥 |
| FR-05 | 元数据校验 | 严格校验字段、类型、长度、栏目和时间 | 非法请求返回字段级错误；不产生半成品文章 |
| FR-06 | 自动归类 | 依据服务端计算的日期与栏目落位 | 跨时区时间在站点时区下归入预期日期 |
| FR-07 | HTML 安全 | 服务端净化并限制外部资源 | `script`、事件属性、表单、嵌入对象等被拒绝或移除；站点布局不被覆盖 |
| FR-08 | 幂等与去重 | 防止网络重试产生重复文章 | 同键同内容返回同一记录；同键不同内容返回 409 |
| FR-09 | 审计 | 记录成功与失败上传的最小必要信息 | 可按请求 ID、上传者、时间和结果定位问题；不保存明文密钥 |
| FR-10 | 配置 | 可配置栏目、站点时区和上传凭据 | 修改后有明确生效方式；启动时发现无效配置则失败并给出错误 |
| FR-11 | 部署 | npm 与 Docker 行为一致 | 两种方式使用同一配置和持久化数据；重启容器后文章不丢失 |
| FR-12 | 健康检查 | 提供不泄露敏感信息的状态接口 | 能区分进程存活和数据库可用；响应中无配置秘密 |

## 8. 交互需求

- 桌面端：时间树主干位于内容视觉中心，日期为主节点；栏目作为向左右伸展的分枝，文章卡片作为叶片。
- 移动端：主干移到左侧，分枝和卡片统一向右排列，避免横向拥挤。
- 滚动时主干具有克制的进度光效；日期节点进入视口时更新当前日期提示。
- 叶片卡片支持鼠标悬停、键盘聚焦和触屏点击；核心信息不能只在悬停时出现。
- 动画只辅助理解时间与层级，不阻塞点击；系统启用“减少动态效果”时关闭位移、视差和连续闪烁。
- 栏目不能只靠颜色区分，必须同时显示栏目文字。
- 主页采用渐进加载；一次追加完整的日期组，避免将同一天拆开。

## 9. 非功能需求

### 9.1 安全

- 生产环境必须使用 HTTPS。
- 密钥仅通过 `Authorization: Bearer ...` 发送，不放入 URL、查询参数、HTML 或常规日志。
- 服务端按允许列表净化 HTML；MVP 不执行上传内容中的 JavaScript。
- 限制请求体、字段长度、标签数量和请求频率。
- 数据库查询参数化；服务端生成文件名/slug，不接受客户端路径。
- 使用严格安全响应头和内容安全策略；外链使用安全的 `rel` 属性。
- 认证失败响应不暴露密钥是否存在、上传者名称或内部实现。

### 9.2 性能与容量（建议默认）

- 目标规模：每天不超过 100 篇、单篇净化前 HTML 不超过 2 MiB、先满足单机部署。
- 首页按游标渐进加载，首屏只加载最近若干日期及其摘要，不传输全文 HTML。
- 动画优先使用 `transform` 和 `opacity`，避免滚动期间频繁触发布局。
- 数据库和内容数据必须位于可备份的持久化目录。

### 9.3 可用性与无障碍

- 支持桌面、平板和手机布局。
- 正文默认字号不小于 16px，常用控件文字不小于 14px。
- 所有功能可由键盘操作；聚焦状态可见；颜色对比满足 WCAG AA 目标。
- 文章列表使用语义化标题、时间和列表结构，时间树装饰不干扰屏幕阅读器。
- 支持 `prefers-reduced-motion`。

### 9.4 可维护性

- 上传协议带 `schemaVersion`，以后新增字段时保持兼容。
- 栏目使用稳定 slug，显示名和颜色调整不影响上传者。
- 数据结构变更通过可追踪迁移完成。
- 提供最少一条从备份恢复到新实例的验证流程。

## 10. 错误与状态约定

| HTTP 状态 | 场景 |
|---:|---|
| 201 | 新文章创建成功 |
| 200 | 相同幂等请求已成功处理，返回既有结果 |
| 400 | JSON 或请求格式无法解析 |
| 401 | 缺失或无效凭据 |
| 409 | 幂等键或外部 ID 与不同内容冲突 |
| 413 | 请求体超过上限 |
| 422 | 字段、栏目、时间或 HTML 规则不符合要求 |
| 429 | 请求频率超过限制 |
| 500/503 | 内部错误或存储暂不可用；返回可追踪的请求 ID |

所有 API 错误使用稳定错误码和结构化字段，不把堆栈、密钥或数据库信息返回给客户端。

## 11. 发布验收清单

- 三个示例栏目在时间树中具有可区分但一致的视觉语言。
- 至少覆盖同日多栏目、同栏目多篇、跨日、空日期范围四种数据情况。
- 无凭据、错误凭据、过大正文、未知栏目、错误时间、重复请求均有自动化测试。
- 使用包含脚本、事件属性、危险 URL、表单和破坏布局样式的样本验证净化策略。
- npm 和 Docker 两条启动路径均完成从上传到阅读的端到端验证。
- 容器重启后文章、栏目和审计记录仍存在。
- 360px 宽移动端、桌面端、键盘操作和减少动态效果模式通过检查。

## 12. 架构决策记录

| 决策点 | 当前建议 | 理由 | 暂不采用 | 状态 |
|---|---|---|---|---|
| 页面与 API | 同一个 TypeScript 全栈应用 | npm/Docker 交付简单，共享校验类型 | 前后端两个独立服务 | 建议默认 |
| 初始存储 | SQLite 单文件数据库 | 单机维护、备份和 Docker 挂载简单 | 首版即使用 PostgreSQL | 建议默认 |
| HTML 存储 | 只保存已净化 HTML，记录原文摘要 | 降低误服务危险原文的风险 | 默认直接保存并服务原始 HTML | 建议默认 |
| 上传认证 | 每个智能体一个可撤销密钥，允许所有者设定其值 | 上传者不可伪造、便于单独吊销和审计 | 所有智能体永久共用一个密码 | 待确认 |
| 栏目管理 | 版本控制中的配置文件 + 启动校验 | MVP 简单、变更可审计 | 首版建设完整后台 | 建议默认 |
| 发布方式 | 校验通过后自动发布 | 符合每日自动生产目标 | 默认人工逐篇审核 | 待确认 |

## 13. 待决策事项（按确认顺序）

### D-01 上传 HTML 的呈现与隔离方式（当前首要问题）

- **方案 A，推荐：统一站点样式。** 提取 HTML 的正文语义，严格删除脚本、内联样式、表单和嵌入对象，由站点统一排版。安全边界最清楚，阅读体验、移动适配和搜索效果最好，但不会保留智能体生成页面的原始视觉样式。
- **方案 B：隔离保留样式。** 在独立来源或强沙箱 iframe 中展示，允许一部分 CSS，仍禁用脚本。更接近上传文件原貌，但部署、响应式、无障碍、搜索和安全维护都更复杂。
- 原始 HTML 与站点同源、允许脚本直接运行的方式风险过高，不列为支持方案。

### 后续待确认

1. 每个智能体独立密钥，还是所有智能体共用一个密码？
2. 校验通过即公开，还是进入待审核区？
3. 读者页面完全公开，还是也需要访问密码？
4. 初期运行地点是个人电脑、NAS、VPS，还是公有云？这会影响 HTTPS、备份和持久化方案。
5. 栏目是否接受修改配置文件并重启生效，还是首版必须有网页管理后台？
6. 是否允许远程图片；若允许，是限制域名、转存到本站，还是直接引用？
7. `publishedAt` 代表文章生成时间、新闻事件时间，还是站点发布时间？
8. 已发布文章是否允许同一智能体覆盖更新，若允许是否保留历史版本？
