# 每日知识时间树网站需求文档

## 2. 产品概述

### 2.1 产品目标

建设一个面向每日内容发布的中文网站。多个自动化智能体每天生成新闻或专业知识类 HTML 文章，通过受保护的接口上传；站点依据日期、栏目、标签和上传者等元数据完成自动分类，并以具有动态交互的“时间树”作为主页核心浏览方式。

### 2.2 成功标准

- 智能体无需人工登录网页即可稳定上传文章。
- 未持有有效凭据的请求无法上传或修改内容。
- 上传内容不能在读者浏览器中执行任意脚本或破坏站点页面。
- 文章上传成功后，能够按站点时区、日期和栏目自动出现在正确位置。
- 读者进入主页首屏即可看到时间轴和真实文章，不需要先越过宣传页。
- 项目可直接通过 npm 运行，并提供等价的 Docker 部署方式。

### 2.3 用户角色

| 角色 | 主要任务 | 权限边界 |
|---|---|---|
| 读者 | 浏览时间树、按栏目或日期筛选、阅读文章 | 完全公开、只读，无需登录 |
| 上传智能体 | 携带共享上传密码和元数据上传或更新文章 | 可创建和覆盖自己的逻辑文章；不能进入管理后台 |
| 站点所有者 | 管理文章、栏目、共享上传密码、站点设置和审计信息 | 使用独立管理员密码登录网页管理后台 |

## 3. 已确认需求

1. 部署以 npm 为首选，同时支持 Docker。
2. 支持自动化智能体上传其每日生成的 HTML 文章。
3. 上传必须经过由站点所有者设定的密码或等价密钥校验。
4. 文章具有日期、栏目、标签、上传者等结构化信息，上传后自动分类。
5. 初始栏目示例包括“科技新闻”“医疗”“密码学”，实际栏目可配置。
6. 主页采用明显、动态、交互性强的时间线；视觉隐喻倾向于“树干 + 树叶”。
7. 本阶段先交付需求文档和设计文档供审核，并创建 Git 仓库。
8. 所有上传智能体共用一个由站点所有者规定的上传密码。
9. 文章完成全部校验、HTML 净化和图片转存后立即公开，不进入人工审核队列。
10. 读者页面完全公开，不要求登录。
11. 初期运行在站点所有者的个人电脑上。
12. 首版必须提供网页管理后台；管理员凭据与共享上传密码分离。
13. 允许文章引用远程图片，但发布前必须下载、验证并转存到本站。
14. 上传元数据中的内容时间代表文章生成时间，时间树据此归档。
15. 允许同一智能体使用稳定外部 ID 覆盖更新既有文章。
16. 上传 HTML 采用统一站点排版：保留正文语义，删除脚本、自带样式、表单和嵌入对象。
17. 每篇文章除当前版本外，只保留最近 1 份历史版本。
18. 管理后台的文章能力限定为浏览、撤下和上传完整更新文件，不直接编辑 HTML 正文；站点时区固定为 `Asia/Shanghai`。
19. 生产入口固定为 `https://codis.fun/Daily/`，本地 Linux 物理机通过 FRP 连接公网服务器，由公网反向代理终止 HTTPS 并按 `/Daily` 子路径转发。
20. 文章发布后自动异步执行正文提取和 TTS（文字转语音），生成可公开播放的音频；TTS 供应商可在管理后台切换和配置。

## 4. MVP 范围

### 4.1 本期包含

- 公开阅读主页：按日期分段展示文章。
- “时间树”交互：中央树干、日期节点、栏目分枝和文章叶片卡片。
- 栏目筛选和日期定位。
- 文章详情页。
- 单篇文章上传 API。
- 上传凭据校验、请求限流、载荷大小限制和审计记录。
- 元数据校验、服务端时间归类、HTML 安全净化、远程图片安全转存、内容去重和幂等处理。
- 基于稳定外部 ID 的文章覆盖更新；失败时保留线上旧版本。
- 管理员登录/退出和会话保护。
- 管理后台：首页概览；文章查询、当前及上一版本预览、撤下、上传完整替换文件；栏目新增、编辑、排序、启停；共享上传密码轮换；TTS 供应商配置；上传、图片与语音任务审计。
- 栏目与站点时区配置，其中栏目由管理后台维护。
- HTML 正文提取、持久化 TTS 任务、音频合成与本站音频存储。
- 每篇文章的朗读入口，以及在 `/Daily` 内持续存在的播放胶囊。
- `/Daily` 子路径部署、FRP 隧道、公网反向代理和 HTTPS 配置示例。
- 空状态、加载状态、错误状态和上传结果反馈。
- npm 开发/生产运行脚本、Dockerfile、Compose 示例、持久化卷和健康检查。
- 基本测试、部署说明、备份与恢复说明。

### 4.2 本期不包含

- 读者注册、评论、点赞、收藏和订阅。
- 智能体在网页中编写文章。
- 富文本编辑器。
- 多管理员、细粒度角色权限、单点登录和找回密码流程。
- 自动抓取外部网页正文；文章内远程图片的受控转存除外。
- AI 自动改写、摘要或自动判断栏目。
- 批量上传、人工审批工作流、邮件/即时消息通知。
- 逐句高亮、朗读播放列表、音频下载、离线播放、跨设备同步和由匿名读者触发语音生成。
- 多机水平扩容和多租户。

以上能力可在后续版本按实际使用情况增加。

## 5. 核心业务流程

### 5.1 智能体上传

1. 智能体生成 HTML 正文和结构化元数据。
2. 智能体使用 HTTPS 请求上传接口，并在 `Authorization` 请求头中携带所有智能体共用的上传密码。
3. 服务端依次执行：认证、限流、请求体大小检查、字段校验、栏目校验、时间归一化、HTML 解析、远程图片安全下载与转存、HTML 净化、内容摘要计算和幂等校验。
4. 全部处理成功后，服务端以事务保存文章和审计信息、立即公开，并返回文章 ID、最终 URL、版本号、内容摘要及归类结果。
5. 同一个幂等键重复提交相同内容时返回原结果；同一个键对应不同内容时拒绝并提示冲突。
6. 上传成功的文章自动出现在对应生成日期和栏目中，不经过人工审核。

### 5.2 智能体更新

1. 智能体使用与创建时相同的 `uploaderId` 和 `externalId` 定位逻辑文章，并携带共享上传密码提交完整新版本。
2. 新版本重新执行与首次上传相同的字段校验、图片转存和 HTML 净化流程。
3. 全部处理成功后才原子替换公开版本，文章内部 ID 和永久链接保持稳定，版本号递增；任一步失败均继续展示旧版本。
4. 管理员已撤下的文章在智能体更新后仍保持撤下，只有管理员能够重新公开。
5. 因所有智能体共用密码，服务端只能记录客户端声明的 `uploaderId`，无法从凭据证明真实调用者确为同一智能体。该限制在管理后台和审计文档中明确显示。

### 5.3 读者浏览

1. 读者打开主页，首屏看到最近日期、时间树主干和至少一组文章叶片。
2. 读者可沿时间树滚动，或使用栏目筛选、日期定位缩小范围。
3. 日期节点下按栏目形成分枝，同栏目的多篇文章按生成时间倒序排列。
4. 点击文章叶片进入详情页；返回时尽量恢复原滚动位置和筛选状态。

### 5.4 管理员操作

1. 站点所有者使用独立管理员密码登录 `/admin`，共享上传密码不能登录后台。
2. 管理员可查看概览，筛选并预览文章的当前版本和最近 1 份历史版本，撤下文章，或上传完整 HTML 文件作为新版本；不提供正文源码编辑器。
3. 管理员可新增、编辑、排序、启用和停用栏目；已被文章引用的栏目不能被破坏性删除。
4. 管理员可设置新的共享上传密码；旧密码失效后，所有智能体需要同步更新。
5. 管理员替换已撤下文章时可明确选择重新公开；智能体上传更新不能自行解除管理员撤下状态。
6. 管理员可配置、测试并启用 TTS 供应商，查看正文提取结果和语音任务，并对失败任务执行重试。

### 5.5 文章朗读

1. 文章通过内容与图片校验后立即公开，同时从净化后的正文提取可朗读文本并创建后台 TTS 任务；语音生成不阻塞文章公开。
2. TTS 任务按供应商限制分段合成，再标准化、拼接为一条逻辑音轨；失败不影响正文阅读，只允许管理员重试。
3. 当前文章版本的音频就绪后，“朗读”按钮可用；生成中或失败时显示明确状态但不暴露供应商错误。
4. 点击“朗读”后弹出固定在页面底部的非模态播放胶囊，支持播放/暂停、前后 15 秒、进度拖动、当前/总时长、倍速和关闭。
5. 播放器在 `/Daily` 站内页面切换时持续播放；刷新后恢复位置但保持暂停，不自动播放。
6. 文章覆盖更新后，旧音频不得作为新正文的音频提供；新版本重新提取和生成，文本与声音配置相同才允许复用缓存。

## 6. 内容与字段定义

### 6.1 上传请求字段

| 中文名 | 字段 key | 类型 | 必填 | 规则 | 来源 |
|---|---|---:|:---:|---|---|
| 协议版本 | `schemaVersion` | string | 是 | MVP 固定为 `1` | 上传者 |
| 外部文章 ID | `externalId` | string | 是 | 与 `uploaderId` 组合唯一，1–100 字符；用于覆盖更新 | 上传者 |
| 标题 | `title` | string | 是 | 去除首尾空白后 1–120 字符 | 上传者 |
| 摘要 | `summary` | string | 否 | 最多 300 字符；空缺时不在 MVP 自动生成 | 上传者 |
| 栏目 | `category` | string | 是 | 必须匹配已启用栏目的稳定 slug | 上传者 |
| 生成时间 | `generatedAt` | ISO 8601 string | 是 | 文章生成时间，必须带时区偏移；服务端转为站点时区归档 | 上传者 |
| 标签 | `tags` | string[] | 否 | 最多 10 个；每个 1–30 字符；规范化去重 | 上传者 |
| 语言 | `language` | string | 否 | 默认 `zh-CN` | 上传者 |
| 来源链接 | `sourceUrl` | string | 否 | 仅允许 `https` URL | 上传者 |
| HTML 正文 | `html` | string | 是 | UTF-8；建议默认上限 2 MiB；必须通过净化 | 上传者 |
| 上传者 | `uploaderId` | string | 是 | 必须匹配后台启用的稳定 ID；因共用密码而属于客户端自报身份 | 上传者 |

### 6.2 服务端生成字段

| 字段 | 用途 |
|---|---|
| `id` | 内部稳定标识 |
| `slug` | 人类可读且唯一的文章 URL 标识 |
| `contentDate` | 根据 `generatedAt` 和 `SITE_TIMEZONE` 计算的归档日期 |
| `contentHash` | 对规范化内容计算的摘要，用于校验与去重 |
| `receivedAt` | 服务端收到本次请求的时间 |
| `publishedAt` | 本版本完成全部校验并公开的服务器时间 |
| `createdAt` / `updatedAt` | 逻辑文章首次创建和最后更新的服务器时间 |
| `version` | 每次有效覆盖更新后递增 |
| `status` | `published` 或 `archived`；校验失败只记审计，不公开 |
| `sanitizerVersion` | 记录使用的 HTML 净化规则版本，便于后续迁移 |

### 6.3 栏目字段

| 字段 | 规则 |
|---|---|
| `slug` | 稳定、唯一，供 API 使用；改显示名时不改变 |
| `name` | 面向读者的栏目名，如“科技新闻” |
| `color` | 时间树分枝和标签的主题色，同时必须有文本标识 |
| `order` | 同一天内的栏目展示顺序 |
| `enabled` | 是否接受新上传和在筛选器中展示 |

## 7. 功能需求与验收条件

| 编号 | 功能 | 需求 | 核心验收条件 |
|---|---|---|---|
| FR-01 | 时间树主页 | 按日期、栏目、文章形成树状时间线 | 最近日期和真实文章在首屏可见；日期顺序稳定；同日多栏目不混排 |
| FR-02 | 筛选与定位 | 支持栏目多选/单选和日期定位 | 筛选后 URL 可表达状态或刷新不丢失；无结果时显示清晰空状态 |
| FR-03 | 文章详情 | 展示标题、日期、栏目、标签、上传者和安全正文 | 刷新可直接访问；危险标签和事件属性无法执行 |
| FR-04 | 上传认证 | 所有智能体使用同一个共享上传密码 | 缺失/错误密码返回通用 401；日志中不出现原始密码；该密码不能登录后台 |
| FR-05 | 元数据校验 | 严格校验字段、类型、长度、栏目和时间 | 非法请求返回字段级错误；不产生半成品文章 |
| FR-06 | 自动归类 | 依据文章生成时间计算日期并按栏目落位 | `generatedAt` 跨时区时在站点时区下归入预期日期 |
| FR-07 | HTML 安全 | 服务端净化 HTML，并把远程图片安全转存到本站 | 危险标签/属性无法执行；远程图片 URL 被改写为本站 URL；站点布局不被覆盖 |
| FR-08 | 幂等与去重 | 防止网络重试产生重复文章 | 同键同内容返回同一记录；同键不同内容返回 409 |
| FR-09 | 审计 | 记录成功与失败上传的最小必要信息 | 可按请求 ID、自报上传者、时间和结果定位问题；不把自报身份描述为已认证身份；不保存明文密码 |
| FR-10 | 配置 | 管理后台可配置栏目和共享上传密码；部署配置可设置站点时区 | 修改后有明确生效方式；无效配置不生效且返回错误 |
| FR-11 | 部署 | npm 与 Docker 行为一致 | 两种方式使用同一配置和持久化数据；重启容器后文章不丢失 |
| FR-12 | 健康检查 | 提供不泄露敏感信息的状态接口 | 能区分进程存活和数据库可用；响应中无配置秘密 |
| FR-13 | 自动公开 | 全部校验、净化和图片转存成功后立即公开 | 公开前不能短暂访问半成品；失败请求不会改变当前公开版本 |
| FR-14 | 网页管理后台 | 所有者可浏览/撤下文章、上传完整更新文件、管理栏目与密码并查看审计 | 未登录不可访问；共享上传密码不可用于后台；无 HTML 正文编辑器；关键操作有确认和结果反馈 |
| FR-15 | 远程图片转存 | 下载文章中的 HTTPS 图片，验证后转存并重写引用 | 私网/本机地址、危险格式、超限图片和异常重定向被拒绝；公开页不再请求原图站点 |
| FR-16 | 覆盖更新 | 相同 `uploaderId + externalId` 可提交完整新版本 | 成功后 ID/永久链接不变、版本递增，只保留当前版与上一版；失败时旧版本不变；管理员撤下状态不被智能体更新解除 |
| FR-17 | 子路径与 FRP 部署 | 站点完整运行在 `https://codis.fun/Daily/`，经公网反向代理和 FRP 到本地 Linux | 任意深层链接可刷新；页面、API、图片、音频和后台均不逃逸到域名根路径；`codis.fun` 其他路径不受影响 |
| FR-18 | 正文提取 | 从方案 A 净化后的 HTML 提取标题、段落、列表、引用等可朗读正文 | 不向供应商发送脚本、样式、导航或原始 HTML；提取结果与文章版本绑定且可在后台预览 |
| FR-19 | TTS 供应商适配 | 后台可配置并切换 TTS 适配器、Base URL、API Key、模型和音色 | API Key 不回显；配置测试有明确结果；切换供应商不修改文章和播放器代码 |
| FR-20 | 异步语音生成 | 发布或覆盖后自动创建持久 TTS 任务，分段合成并生成 MP3 | TTS 失败不影响文章公开；进程重启可继续任务；旧版本结果不能挂到新版本 |
| FR-21 | 朗读与播放胶囊 | 每篇文章显示状态化朗读按钮，音频就绪后弹出底部播放器 | 支持播放/暂停、±15 秒、进度、时长、0.75–2 倍速和关闭；不自动播放；音频支持 Range 请求 |

## 8. 交互需求

- 桌面端：时间树主干位于内容视觉中心，日期为主节点；栏目作为向左右伸展的分枝，文章卡片作为叶片。
- 移动端：主干移到左侧，分枝和卡片统一向右排列，避免横向拥挤。
- 滚动时主干具有克制的进度光效；日期节点进入视口时更新当前日期提示。
- 叶片卡片支持鼠标悬停、键盘聚焦和触屏点击；核心信息不能只在悬停时出现。
- 动画只辅助理解时间与层级，不阻塞点击；系统启用“减少动态效果”时关闭位移、视差和连续闪烁。
- 栏目不能只靠颜色区分，必须同时显示栏目文字。
- 主页采用渐进加载；一次追加完整的日期组，避免将同一天拆开。

## 9. 非功能需求

### 9.1 安全

- 生产环境必须使用 HTTPS。
- 密钥仅通过 `Authorization: Bearer ...` 发送，不放入 URL、查询参数、HTML 或常规日志。
- 共享上传密码与管理员密码必须不同、分别散列保存和独立轮换；上传密码不授予管理权限。
- TTS API Key 与上述两种密码再次分离，加密入库；主加密密钥只来自环境或 Docker Secret。
- 服务端按允许列表净化 HTML；MVP 不执行上传内容中的 JavaScript。
- 远程图片下载器必须阻止环回、局域网、链路本地、保留地址和云元数据地址，限制重定向、超时、字节数、像素数及 MIME，并对安全格式重新编码后再保存。
- 文章只有在所有必需图片成功转存后才自动公开；失败时整次创建或更新失败。
- 限制请求体、字段长度、标签数量和请求频率。
- 数据库查询参数化；服务端生成文件名/slug，不接受客户端路径。
- 使用严格安全响应头和内容安全策略；外链使用安全的 `rel` 属性。
- 认证失败响应不暴露密钥是否存在、上传者名称或内部实现。
- 公网服务器只公开 80/443；FRP 数据端口、仪表盘、本地应用端口和数据库不得直接暴露。反向代理覆盖不可信转发头，应用只信任配置的代理来源。

### 9.2 性能与容量（建议默认）

- 目标规模：每天不超过 100 篇、单篇净化前 HTML 不超过 2 MiB、每篇远程图片不超过 20 张，先满足个人电脑单机部署。
- 首页按游标渐进加载，首屏只加载最近若干日期及其摘要，不传输全文 HTML。
- 动画优先使用 `transform` 和 `opacity`，避免滚动期间频繁触发布局。
- 数据库和内容数据必须位于可备份的持久化目录。
- 本地图片使用内容摘要去重并设置尺寸，避免重复占用磁盘和页面布局跳动。
- TTS 使用 SQLite 持久任务和独立 worker，默认低并发；长文本按供应商上限切分，最终音频以内容摘要去重。
- MP3 支持 HTTP Range、ETag 和正确 MIME；音频生成不占用跨 FRP 的长连接。

### 9.3 可用性与无障碍

- 支持桌面、平板和手机布局。
- 正文默认字号不小于 16px，常用控件文字不小于 14px。
- 所有功能可由键盘操作；聚焦状态可见；颜色对比满足 WCAG AA 目标。
- 文章列表使用语义化标题、时间和列表结构，时间树装饰不干扰屏幕阅读器。
- 支持 `prefers-reduced-motion`。
- 播放胶囊是非模态区域，不锁定焦点；所有控件支持键盘和读屏，移动端不遮挡正文及系统安全区。

### 9.4 可维护性

- 上传协议带 `schemaVersion`，以后新增字段时保持兼容。
- 栏目使用稳定 slug，显示名和颜色调整不影响上传者。
- 数据结构变更通过可追踪迁移完成。
- 覆盖更新使用稳定逻辑 ID 和递增版本号；每篇只保留当前版和最近 1 份历史版，更早正文、图片和音频在安全延迟后清理，最小审计事件继续保留。
- TTS 业务层只依赖供应商适配接口；兼容统一协议的厂商可只换 Base URL、API Key、模型和音色，协议或签名不同的厂商增加新适配器。
- 提供最少一条从备份恢复到新实例的验证流程。

## 10. 错误与状态约定

| HTTP 状态 | 场景 |
|---:|---|
| 201 | 新文章创建成功 |
| 200 | 相同幂等请求已成功处理，返回既有结果 |
| 400 | JSON 或请求格式无法解析 |
| 401 | 缺失或无效凭据 |
| 409 | 幂等键或外部 ID 与不同内容冲突 |
| 413 | 请求体超过上限 |
| 422 | 字段、栏目、时间或 HTML 规则不符合要求 |
| 424 | 远程图片无法安全获取或处理，文章未发布 |
| 429 | 请求频率超过限制 |
| 500/503 | 内部错误或存储暂不可用；返回可追踪的请求 ID |

所有 API 错误使用稳定错误码和结构化字段，不把堆栈、密钥或数据库信息返回给客户端。

## 11. 发布验收清单

- 三个示例栏目在时间树中具有可区分但一致的视觉语言。
- 至少覆盖同日多栏目、同栏目多篇、跨日、空日期范围四种数据情况。
- 无凭据、错误凭据、过大正文、未知栏目、错误时间、重复请求均有自动化测试。
- 使用包含脚本、事件属性、危险 URL、表单和破坏布局样式的样本验证净化策略。
- 使用本机地址、私网地址、DNS 重绑定、重定向链、伪造 MIME、超大文件、解码炸弹和 SVG 样本验证图片转存策略。
- 管理后台覆盖登录保护、文章浏览、撤下、完整文件更新、栏目管理、密码轮换、TTS 配置及审计查看，并确认不存在 HTML 正文编辑入口。
- 创建后使用同一 `uploaderId + externalId` 更新：成功时 URL 不变且内容替换，失败时仍显示旧版本。
- 第三次覆盖后只保留当前版本和最近 1 份历史版本；更早媒体不会被公开或误删仍在使用的共享文件。
- `https://codis.fun/Daily/`、文章深层链接、API、图片、音频和后台登录在 FRP 链路下工作，且域名其他路径不受影响。
- 上传成功后文章立即匿名可读，TTS 进入异步状态；供应商失败不影响正文，管理员可在后台查看脱敏原因并重试。
- 当前版音频与文章版本一致；更新后旧音频不会冒充新正文音频，撤下文章后正文和音频均匿名返回 404。
- 播放胶囊在 320px 宽度、键盘、读屏、200% 缩放及减少动态效果模式下可操作；MP3 拖动请求返回 206。
- npm 和 Docker 两条启动路径均完成从上传到阅读的端到端验证。
- 容器重启后文章、栏目和审计记录仍存在。
- 360px 宽移动端、桌面端、键盘操作和减少动态效果模式通过检查。

## 13. 决策事项

### 13.1 已确认：D-01 上传 HTML 的呈现与隔离方式

- **已选择方案 A：统一站点样式。** 提取 HTML 正文语义，严格删除脚本、内联样式、表单和嵌入对象，由站点统一排版。
