## 追加：真正的 3D Cover Flow —— 侧边卡片"立起来"

**需求**：侧边卡片应该是绕竖轴**竖立**着（rotateY），不是缩小平放。

**核心结论（最容易踩的坑）**：
`perspective` **不能**加在父级 `.coverflow-stage` 上。父级透视的消失点在舞台中心，
而侧边卡片被 `--shift` 推到离中心约 300px 处再转 ~54°，等于用极偏的视角去看一个斜面板，
`matrix3d` 实测被压成 98px / 37px 的细缝（几乎侧向消失）。
**正确做法：每张卡片自己带 `perspective()`**（写在 transform 列表最前面），
消失点即卡片自身中心，卡片才能"原地立起来"。

**第二个必要条件**：`transform-origin` 必须落在同一点，否则左右不对称。
原来靠 `translate(-50%, -50%)` 居中，此时 `transform-origin` 是**布局盒子中心**
（`left:50%` 使盒子中心偏在舞台中心右侧 1/2 卡宽处），左右两张卡片的眼点会差 500px 以上。
改成用负外边距居中布局盒子：
```css
margin-top: calc(var(--card-size) / -2);
margin-left: calc(var(--card-size) / -2);
```
之后 `transform-origin` 恒为舞台中心，透视消失点统一，`translate3d` 里也不用再写 `-50%`。

**最终参数**（桌面）：
```css
--persp: 1100px;
--rot:  calc(47deg + var(--distance, 0) * 7deg);   /* d1→54°, d2→61° */
--shift: calc(70% + (var(--distance, 1) - 1) * 30%);
--depth: calc(var(--distance, 0) * -46px);
transform: perspective(var(--persp)) translate3d(±var(--shift) + var(--drag-offset), 0, var(--depth)) rotateY(∓var(--rot));
```
`rotateY` 正角让外侧边后退、内侧边前移 —— 侧边封面"朝向中心"，这是 Cover Flow 的关键朝向。

**窄屏**（`@media (max-width:760px)`）另配一套，否则第二张侧卡会被视口硬切：
`--card-size: clamp(13.5rem,58vw,19rem)`、`--rot: 48deg+7deg`、`--shift: 50%+14%`、`--persp: 900px`。

**验证方法（关键）**：这个模型读不了 PNG（返回 content filtered），所以改用**矩阵反推**校验：
读 `getComputedStyle(card).transform` 的 `matrix3d`，用 `x_s = x·d/(d−z)` 手算四个角，
与 `getBoundingClientRect` 对比。1440×900 实测 d1 宽 157px、bbox 中心比变换中心内移 23.5px，
手算 156.9px / 23.5px —— 完全吻合；左右两卡矩形精确镜像（L[-349,-192] ↔ R[192,349]）。
`m11 = 0.587785 = cos54°` 也印证了角度链路。
**结论：改 3D/transform 时，用 matrix3d 反推比截图肉眼更可靠。**

**回归检查**：8 种视口全部 `scrollHeight <= innerHeight` 且 `scrollWidth <= innerWidth`（无横竖滚动），
侧卡不会被视口硬切。倒影无回归：侧卡本来倒影就落在 y≈882 之后（区块 `overflow:hidden` 裁在 900），
原先也只露 18px，现在转角变大后完全不露 —— 与改动前等价，非新问题。

## 追加：更激进的转角 + 修掉两个真 bug（横向剪切、纵深不足）

**需求**：转角更激进；用户觉得左右旋转方向反了。

### bug 1：横向位移写在透视组"里面"→ 卡片被剪成窄缝
`perspective(d) translate3d(S,0,0) rotateY(θ)` 是**错的**：卡片被 S 推到偏心后，
左右两端的 z 不同，同一个 S 被两个不同的透视缩放因子（d/(d−z)）放大/缩小，
两端相向收敛 → 52° 时本应 242px 的卡片只剩 **157px**。
**正确**：把横向位移写到 `perspective()` **左侧**（投影完再平移）：
```css
transform: translate3d(S,0,0) perspective(var(--persp)) translateZ(var(--depth)) rotateY(θ);
```
（transform 列表从右往左作用，所以最左边的 translate3d 最后生效 = 屏幕空间平移。）
同角度下宽度 157 → 242px。

### bug 2：纵深不够 → 侧卡比中间卡片还高（最影响观感的一条）
近端 z = `--depth + (卡宽/2)·sinθ`。当 depth 只有 -70px、θ=64° 时近端 z = **+118.7**，
即跑到中间卡片平面（z=0）**前面**去了，透视把它放大 1.135 倍 → 高 **477 > 中间卡片 420**。
苹果 Cover Flow 里侧边封面永远比中间小，所以这看着很别扭。
修法：让 `|depth| > (卡宽/2)·sinθ`，并改成**按卡宽取比例**（视口压小卡片时比例不失真）：
```css
--persp: calc(var(--card-size) * 2.4);
--depth: calc(var(--distance, 0) * var(--card-size) * -0.57);
```
修后 1440×900：侧卡 152×400 vs 中间 420×420 —— 长宽都更小，且由中心向外
高度 420→400→329 单调递减，正是 Cover Flow 的"山丘"剪影。

### 关于"左右搞反了"——查证结论：当前方向是对的
查了 Chrome 团队 Bramus 做的官方 Cover Flow 复刻（scroll-driven-animations.style）：
```css
0%   { transform: translateX(-100%) rotateY(-45deg); }  /* 左侧 → 负角 */
100% { transform: translateX(100%)  rotateY(45deg); }   /* 右侧 → 正角 */
```
即**左侧卡 rotateY 负、右侧卡正**，与本项目实现一致（`is-left` 用 `-1 * rot`）。
物理上也自洽：封面像唱片架/旋转木马那样**朝外**立着，靠中心的那条边离观察者更近。
也有反过来的写法（某旧博客把左侧元素给 +42°），但那与官方复刻不符。
因此把方向做成**一个变量** `--turn`（1=原生 / -1=镜像），要翻只需改一个数字。
用户仍觉得反的话，`--turn: -1` 即可，无需改结构。

**结果**（1440×900，`--rot: 56deg+8deg·d`、`--shift: 64%+25%`）：
`L[-333,-181]h400 / A[-210,210]h420 / R[181,333]h400`，左右精确镜像；
8 视口全部单屏无溢出；360 宽下最外侧 177 < 视口半宽 180（刚好放得下）。

## 修复：后台新增栏目报 INVALID_CATEGORY

**现象**：管理后台「栏目」→ 填写信息 → 点【保存栏目】→ 提示 `INVALID_CATEGORY`。

**根因（真 bug，非用户填错）**：表单里 slug 的 `pattern="[a-z0-9][a-z0-9-]*"` **根本没生效**。
HTML 的 `pattern` 属性现在按 **RegExp 的 `v` 标志**编译，而 `v` 模式下字符类里**未转义的尾部
`-`** 是非法的 → 整个 pattern 编译失败 → 按规范**编译失败的 pattern 会被浏览器静默忽略**
→ `patternMismatch` 对所有输入都是 `false`。于是 `AI` / `人工智能` / `ai_news` / `-ai` 全都能提交，
打服务端的 Zod 正则被拒，只返回一个**不带字段名的** `INVALID_CATEGORY`。

**怎么发现的**（可复用）：没有靠猜，也没法登录后台（密码是 DB 里的 hash），改用两条探针：
1. 从 `components/admin-dashboard.tsx` 抄出实际的 `pattern` 值，在真实浏览器里
   `new RegExp("^(?:"+P+")$","v")` 试编译 + 造 `<input pattern=P>` 逐个塞值看 `validity.patternMismatch`
   —— 这一步直接暴露"全部放行"。
2. 在 Node 里用项目自带的 zod 复刻 route 的 schema，跑一张输入矩阵，看清服务端到底卡哪个字段。

**修法**：
- `lib/constants.ts` 新增 `CATEGORY_SLUG_PATTERN = '[a-z0-9][a-z0-9\\-]*'`（**连字符必须写 `\-`**），
  前端 `pattern={CATEGORY_SLUG_PATTERN}`、服务端 `.regex(new RegExp(\`^${CATEGORY_SLUG_PATTERN}$\`))`
  **共用同一份来源**，从机制上杜绝两边规则漂移。
- 顺带补齐表单与服务端的对齐：slug `maxLength=60`、name `maxLength=40`、sortOrder `max=10000`
  （原先只有 `min=0`，超过 10000 也会被服务端拒），并给 slug 加了 placeholder/title 说明规则。
- **让错误可诊断**：`app/admin/api/categories/route.ts` 的 422 现在回传 `fields: [...]`；
  `call()` 把它挂到 Error 上，`saveCategory` 翻译成中文提示（如「保存失败：Slug 不符合要求…」）。
  这条很重要——原来所有字段错误都只显示一句 `INVALID_CATEGORY`，无法定位。
- 新增 `tests/category-slug-pattern.test.ts`：用 **`v` 标志**断言 pattern 可编译，
  并校验前后端语义一致。已验证旧值 `[a-z0-9][a-z0-9-]*` 会被这个测试判失败（即真能防回归）。

**验证**：typecheck 通过；全量 30 个测试 29 过 1 败（唯一失败仍是既有的 `html.test.ts` DNS 环境问题）；
编译产物实测为 `const CATEGORY_SLUG_PATTERN = '[a-z0-9][a-z0-9\\-]*'`（运行时字符串正确带反斜杠）。

**教训（通用）**：HTML 的 `pattern` / `RegExp(v)` 这类"编译失败即静默失效"的校验，
**必须有测试用真实标志去断言它能编译**，否则它看起来是一道防线、实际是空的。

## 追加：把 base64 图片的真实体积上限写进 agent-kit

**需求**：用户怀疑 HTML 内嵌 base64 图片的上限是 2MB，希望写进 agent-kit 的 README / 提示词，

**换算**：base64 膨胀 4/3 ≈ 1.33 倍 ⇒ 2MB 的 HTML 大约只能装 **1.4MB 原图**。

## 修复：git 报 bad object HEAD（已解决）

**症状**：`git status` → `fatal: bad object HEAD`；`git log` → 同样；
`git show HEAD:<path>` → "exists on disk, but not in 'HEAD'"；`git stash` 静默失败。
但 `git rev-parse HEAD` 能返回 `c76caf19`，`git diff <某些文件>` 也能出结果 —— 很迷惑。

**真正原因（排除了几个错误猜测）**：
- ❌ 不是沙箱读拦截：pack 文件能直接 `head` 读出 `PACK\0\0\0\002`，`git verify-pack` 两个 pack 都是 ok。
- ❌ 不是 partial clone：`remote.origin.promisor` / `partialclonefilter` 均为空，`repositoryformatversion=0`。
- ✅ **是"引用指向了本地不存在的 commit"**：`refs/heads/main` 已是 `c76caf19`，
  但本地对象库里没有它（本地能枚举到的 commit 只到 `be6e99f`，9 月 9 日）。
  而 `git ls-remote origin` 显示**远端 HEAD 就是 `c76caf19`** —— 远程有、本地丢了。

**修法**：`git fetch origin main`。只补对象，不动 `refs/heads`、不碰工作区，安全。
取回后 `git cat-file -t c76caf19` → `commit`，`git log --oneline -5` 正常，
`git status` 正常列出 17 改 3 新（`git diff --stat` 也能用了）。

**fetch 时冒出的另一批报错（未处理，需用户确认）**：
```
error: refs/codex/turn-diffs/checkpoints/... does not point to a valid object!
fatal: bad object refs/codex/turn-diffs/captures/.../base
error: failed to perform geometric repack
```
这是一批 `refs/codex/*` 残留引用（某个 Codex 类工具的遗留，与本项目无关）指向缺失对象，
导致 fetch 末尾的自动 repack 失败。**不影响取回对象，也不影响日常 git 操作**，
但会持续刷错误并挡住 `gc`。删引用有破坏性，**没擅自清理**。

**结论**：之前多轮里我说"沙箱 git 坏掉、建议你在本地提交"这个判断不准确 ——
真实原因是引用与对象不一致，fetch 一下就修好了。**现在可以在这里正常提交。**
